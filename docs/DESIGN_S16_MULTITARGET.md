# S16 多目标监测 —— 专题设计

> 对应 [DESIGN.md](DESIGN.md) §16 展开项「多目标监测」、[DEVELOPMENT_PLAN.md](DEVELOPMENT_PLAN.md) S16。
> 本文定义 S16 的行为与数据迁移方案，是 S16 编码的唯一依据；实现冲突时以本文为准。

---

## 一、目标与边界

### 1. 目标

同时监测多个目标（IP / 主机名 + 可选端口），各目标的检测、记录、连续失败计数、告警去重与界面展示**互不干扰**。

### 2. 不做（划归后续子迭代）

- 逐目标间隔 / 超时 / 端口策略覆盖（S16b）
- 逐目标告警阈值覆盖（S16b）
- 目标分组、目标级保留期（不在 S16 范围）
- 目标列表批量导入导出（S15 模板能力，另议）

### 3. 兼容底线

- 升级后**旧配置与旧数据必须无损可用**，单目标用户的观感与行为保持不变（默认即一个目标）。
- 不新增必填配置项；配置文件缺失字段一律取默认值。

---

## 二、子迭代拆分

| 子迭代 | 范围 | 收口标准 |
| --- | --- | --- |
| **S16a 多目标基础**（本次） | 目标实体、配置 v2 与迁移、记录关联目标、每目标告警计数、调度多目标并行、界面按目标展示与筛选、工具条选定目标 | 配置多个目标后并行检测，各目标记录 / 告警 / 状态互不干扰；旧配置旧数据升级后可用 |
| S16b 逐目标策略 | 每目标间隔 / 超时 / 端口策略 / 告警阈值覆盖；设置页目标明细编辑；调度按目标周期独立计时 | 不同目标可按各自间隔与策略运行 |
| S16c 多目标打磨 | 目标分组与排序持久化、按目标清空 / 导出默认文件名、托盘与告警文案细化 | 多目标场景的查询与运维操作齐备 |

## 三、目标实体

### 1. 字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 目标标识，新建为 Guid（N 格式）；v1 迁移目标固定为 `default`（见第五节） |
| `name` | string? | 显示名，可为空；为空时界面以地址显示 |
| `targetIp` | string | IP 或主机名，校验规则同 v1（IPv4/IPv6/RFC 主机名） |
| `port` | int? | 可选端口，1~65535，空表示不检测端口 |
| `enabled` | bool | 是否参与调度，默认 true |

- 显示地址 = `targetIp[:port]`；显示名 = `name` 非空则取 `name`，否则取显示地址。
- 同一 `targetIp + port` 不允许重复添加（保存校验拦截）。
- 至少保留 1 个目标；禁止删除最后一个目标。

### 2. 检测参数归属（S16a）

检测间隔、超时、端口检测策略、告警阈值与告警通道仍为**全局共享**（沿用设置页 b) / c) 组），作用于所有目标；逐目标覆盖在 S16b 引入。

## 四、配置结构 v2 与迁移

### 1. 结构变化

```
MonitorConfig
├── configVersion: 2
├── detection: { interval, timeoutMs, portPolicy }      ← 目标相关字段移出
├── targets: [ { id, name, targetIp, port, enabled } ]  ← 新增
├── alert / storage / interface / startup               ← 不变
```

`detection.targetIp` 与 `detection.port` 降级为**迁移输入**：读取后用于构造首个目标，随后置空，不再写出。

### 2. 迁移规则（读取配置时执行）

1. `targets` 缺失或为空：
   - 用旧 `detection.targetIp`（缺省 `127.0.0.1`）与 `detection.port` 构造唯一目标；
   - 该目标 `id = "default"`、`enabled = true`、`name` 为空。
2. `targets` 已存在：保持原样，仅清理迁移输入字段。
3. 迁移后在内存中把 `configVersion` 置为 2；下次保存即写为新结构。
4. 迁移幂等：重复读取不会重复创建目标。

> 版本号语义：结构变更才递增。v1 文件（无 `targets`）按上述规则平滑升级，无需用户干预。

## 五、数据迁移（SQLite）

### 1. 表结构

`detect_record` 与 `alert_record` 各新增一列：

```sql
target_id TEXT NOT NULL DEFAULT ''
```

并新增组合索引 `(target_id, timestamp)`；原 `timestamp` 索引保留。

### 2. 存量数据归属

- 建表 / 补列后，一次性把 `target_id = ''` 的历史行回填为 `'default'`，与 v1 迁移目标的 Id 对齐。
- 回填幂等；新库无历史行时无操作。
- 若用户删除 `default` 目标，这些历史记录仍可通过「全部目标」筛选查阅，不删除数据。

### 3. 写入与查询

- 每条记录写入时携带当时的 `target_id`（目标删除后仍可追溯其历史）。
- 加载支持按目标过滤；过滤为空表示全部目标（保持向下兼容的调用方式）。

---

## 六、调度行为

- 启动时为启用目标集合生成一次快照，按全局间隔循环。
- **每个周期内所有启用目标并行检测**，互不阻塞（单个目标超时不影响其余目标）。
- 暂停 / 恢复 / 停止语义不变：暂停期间不检测、不计数、不告警；恢复后连续失败计数延续。
- 单个目标检测链异常仅记录日志，不终止调度循环，也不影响其他目标。
- 启用目标为 0 时不允许启动（按钮禁用并提示）。

---

## 七、告警行为

- 连续失败计数、告警去重状态、最近失败记录**按目标独立维护**。
- 阈值与「端口失败是否计入」仍取全局配置，每次判定时读取（保存后立即生效）。
- 冷启动延续按目标分别读取：各自最近一条检测记录的连续失败计数与最近失败摘要。
- 启动即达阈的立即告警同样按目标判定，可能一次启动产生多条告警。
- 告警记录写入 `alert_record` 并携带 `target_id`；弹窗 / 托盘通知内容含目标显示名与地址。
- 某目标恢复成功仅重置该目标的计数与去重状态。

---

## 八、界面行为

### 1. 仪表盘

- 顶部大标识为**汇总状态**：告警中优先；否则取所有目标最近状态的「最差」（异常 > Ping 失败 > 端口失败 > 成功）。
- 新增「目标状态」区块：每行展示目标显示名、地址、状态色块与文案、最近延迟、连续失败次数、最近检测时间。
- 最近记录简表新增「目标」列，仍按时间倒序取最近若干条（跨目标）。

### 2. 日志页 / 告警历史页

- 筛选条新增「目标」下拉：`全部目标` + 各目标显示名（含已禁用目标，便于查历史）。
- 表格保留「目标 IP / 端口」列以区分目标；导出与清空语义不变（清空仍为全部目标，二次确认文案明确「全部目标」）。

### 3. 设置页

- a) 目标设置改为目标列表：可编辑名称、IP、端口、启用；支持新增 / 删除。
- 行内校验：地址合法性、端口范围、重复目标、至少保留 1 个目标；错误汇集在列表下方提示。
- b) 检测设置、c) 告警设置保持全局共享；「保存后按新配置重启调度」同样适用于目标增删改。
- 目标增删改属于「保存后生效」，未保存的草稿不参与调度。

### 4. 工具条

- 显示目标选择下拉：`汇总（全部目标）` + 各启用目标，默认汇总。
- 选定目标后色块、状态文案、延迟、连续失败次数均取该目标；告警标记随该目标。
- 选择为**运行期状态**（不写配置文件），重启后回到汇总视图。

### 5. 托盘

- 悬浮提示展示汇总状态与目标数量；菜单启停作用于全部启用目标。

---

## 九、异常与边界

| 场景 | 行为 |
| --- | --- |
| 目标全部禁用 | 保留目标与历史；禁止启动并提示「没有启用的目标」 |
| 目标在运行中被删除 / 禁用 | 保存后按新目标集合重启调度；历史记录保留 |
| 记录的 target_id 找不到对应目标 | 界面显示其 IP / 端口（历史可查），筛选器仅列当前目标 + 全部 |
| 写库降级 | 与 v1 一致：仅内存，界面提示，不中断检测 |
| 迁移失败（配置损坏） | 回退默认配置（单目标 127.0.0.1），不影响启动 |

## 十、验收（P0 手测）

1. 旧配置（v1）+ 旧数据启动：目标自动迁移，历史记录可见并可筛选到该目标。
2. 配置 2 个目标（1 个不可达），启动后并行检测：可达目标成功、不可达目标 Ping 失败，互不影响。
3. 不可达目标连续失败达阈：仅该目标告警一次，另一目标无告警；恢复后该目标重置。
4. 仪表盘、日志页、告警历史页、工具条、托盘五处状态与目标一致。
5. 删除目标并保存：调度按新集合重启，被删目标历史仍可在「全部目标」下查看。
6. 重启进程：各目标连续失败计数分别延续，达阈目标按规则再次告警。
