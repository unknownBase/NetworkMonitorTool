# 开发推进计划（DEVELOPMENT_PLAN）

将 [ROADMAP.md](../ROADMAP.md) 的里程碑拆解为可执行的迭代（Sprint），每个迭代以「可构建、可演示」为收口标准。
行为定义以 [docs/DESIGN.md](DESIGN.md)（总体设计说明）为唯一依据，本文件只排顺序、不定细节。

## 各迭代任务清单

### S1 工程骨架

- [x] 创建 `Models/ Services/ ViewModels/ Views/ Converters/` 目录并迁移代码
- [x] 引入 NuGet：`Microsoft.Extensions.Hosting`、`CommunityToolkit.Mvvm`、`WPF-UI`、`Microsoft.Data.Sqlite`
- [x] App.xaml 接入泛型主机（`Host.CreateDefaultBuilder`），DI 注册占位
- [x] 全局异常处理：`DispatcherUnhandledException` + `TaskScheduler.UnobservedTaskException` → 写日志并提示
- [x] `.gitignore`（bin/obj/.vs/*.user/本地数据）、`AssemblyInfo` 版本号
- [x] `AppPaths` 数据目录可配置（storage.dataDirectory，默认为用户目录；配置文件固定存默认目录）

### S2 检测核心

- [x] `DetectionStatus` 枚举（成功 / Ping失败 / 端口失败 / 异常 / 暂停中 / 告警中）与状态→颜色转换器
- [x] `PingProbe` + `TcpPortProbe`（超时、错误摘要区分超时/不可达/权限）
- [x] `IDetectionService`：单次检测编排，端口策略四分支（策略 UI 在 S10 补全，先实现逻辑）
- [x] `ISchedulerService`：周期触发（间隔时/分/秒），启动/停止/暂停/恢复，与页面解耦
- [x] 控制台验证驱动 `tools/DetectorConsole`（复用 `AddDetectionCore` DI 注册，驱动周期检测并输出结果）

### S3 存储与配置

- [x] SQLite 建表：`detect_record`、`alert_record`（分表）
- [x] `IStoreService`：逐条写入、按保留期加载、清空；写入失败降级为仅内存 + 界面提示
      （降级经 `IStoreService.WriteFailed` 事件上报，界面提示条随 S4/S5 页面接入）
- [x] `MonitorConfig` 等模型 + 配置版本号；`%LOCALAPPDATA%\NetworkMonitorTool\appsettings.json` 读写，缺失字段取默认
- [x] 数据目录配置项 `storage.dataDirectory`：由 `IConfigService` 统一接管读取（已移除 `AppPaths` 内的临时解析），
      校验合法性（绝对路径、盘符就绪、可写探测、剩余空间），不合法回退默认目录
- [x] `IDataMigrationService`：保存并切换数据目录时，将数据库（含 -shm/-wal）、日志复制到新目录，验证（integrity_check +
      记录数比对）成功后重写配置并切换；失败清理副本、保持原目录并提示，不丢数据
- [x] `ICleanupService`：按保留天数删除过期记录（`CleanupHostedService` 启动一次 + 每小时）

> S3 收口验证（`tools/DetectorConsole`，均通过）：
> 1. 跨进程不丢记录：一轮运行入库 N 条后退出，`--load-only` 可回读同样条数。
> 2. 配置兼容：仅含部分字段的手写 appsettings.json 读入后缺失字段全部取默认；写回后版本号与默认目录语义正确。
> 3. 校验拦截：非法 IP / 越界端口不写入配置（返回错误项列表）。
> 4. 目录迁移：`--migrate <新目录>` 成功切换且记录/告警在新目录可查；`--migrate Q:\...` 磁盘未就绪时失败回退，原目录数据仍可回读。
> 5. 分表与清理：`--seed` 写入超期检测样本 + 告警样本，保留期窗口回读正确过滤，按保留天数清理只删超期记录。
> 6. 降级：数据库不可写（monitor.db 被目录占用）时记录仅落内存并触发降级提示，调度循环不中断。
> 7. 主程序启动：Release 构建下 WPF 主窗口正常启动，启动即执行一次清理并写日志到生效数据目录。

### S4 页面框架

- [x] `ShellViewModel`：导航命令、当前页、全局状态、上次停留页记忆
- [x] 主窗口：左导航 + 右 ContentControl，顶/底栏全局状态标识
- [x] 仪表盘页 VM：状态大标识、目标摘要、最近检测时间/延迟/连续失败数、快捷操作、简表跳转
- [x] 设置页 VM：六组配置分区（含存储组的数据目录选择，目录浏览对话框）、保存/恢复默认/取消、行内校验、未保存切页确认
- [x] 关于页 VM：版本、配置/数据库/日志路径

> S4 收口验证（均通过）：
> 1. 构建：`dotnet build -c Release` 0 警告 0 错误（主程序与 `tools/DetectorConsole` 均通过）。
> 2. 配置兼容：S3 时期不含 `interface` / `startup` 两段的 appsettings.json 正常读入（新字段取默认），保存后写回含完整六段且版本号不变。
> 3. 启动冒烟：`storage.dataDirectory` 指向临时目录时，数据库与日志均落在该目录，主窗口标题为「网络连通性监测工具 - 仪表盘」（默认首页），`error.log` 未产生。
> 4. 设置页保存：修改目标 IP / 间隔 / 关闭行为后保存，配置落盘且调度按新参数重启周期（保存后生效）。
> 5. 关闭收口：点关闭 → 进程正常退出，无未捕获异常（修正 `OnClosing` 在关闭序列内重入 `Close()` 抛 `InvalidOperationException` 的缺陷）。
> 6. 待人工点击项：五页导航切换与未保存时的「保存 / 放弃 / 取消」拦截、目录浏览对话框（需在图形界面逐页点测，不纳入自动回归）。

> 本迭代只落页面与配置项，不实现后续行为：工具条按钮（S8）置灰并提示，「关闭主窗口时」与「开机自启」（S9/S10）仅保存配置，页面内给出待交付说明。

## 依赖与风险

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| WPF-UI 版本与 .NET 8 兼容矩阵 | S1 阻塞 | S1 首日锁定版本并跑通托盘 Demo |

| 开机自启路径含空格 | 自启失败 | 注册表值加引号，S10 覆盖用例 |
| 多目标监测侵入面广（S16） | 影响已交付的 v1.0 | 先出专题设计与数据迁移方案，保留单目标兼容路径，拆子迭代交付 |
| 邮件 / Webhook 依赖外部网络与凭据（S14） | 告警静默失败 | 后台发送 + 失败降级提示，凭据本地加密存储 |
| 归档压缩占用 CPU / IO（S12） | 影响检测实时性 | 低优先级 / 空闲时段后台归档 |
| 图表大数据量渲染卡顿（S13） | UI 卡顿 | 聚合采样 + 虚拟化 |
| 可选增强行为未定义即开工 | 行为偏离 DESIGN | 每项先在 DESIGN §16 展开完整行为说明再排期 |

2. 行为与 DESIGN 文档对应章节逐条对得上，冲突时以文档为准并在提交中说明。
3. 用户可见变更同步 CHANGELOG.md；里程碑结束更新 ROADMAP.md 勾选状态。
4. 对应 P0 手测用例通过并记录（见迭代收口标准）。
